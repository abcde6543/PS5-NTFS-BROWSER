## NTFS Browser v1.4.0 for jailbroken PS5

Browse, copy to and from, upload to, and now **delete from** NTFS USB drives on a jailbroken PS5.

### Download
**`ntfs-browser.elf`**: send it to your ELF loader (port 9021, e.g. elfldr, or etaHEN's payload loader):

```sh
nc -q0 <ps5-ip> 9021 < ntfs-browser.elf
```

The PS5 browser opens on the file browser. You can also use `http://<ps5-ip>:8085` from a phone or PC.

### What's new in 1.4.0
- **Delete files and folders on NTFS drives.** Select items and press **Delete**, click the trash icon on a row, or press the Delete key. Folders are deleted with everything in them, in the background, with progress in **Transfers**.
- **One-time confirmation.** The first time you delete on a device, NTFS Browser asks once, explaining there's no recycle bin. After that, deleting is immediate. You can turn the question back on under **Settings** (the new gear icon).
- Handles Windows' 8.3 short names (both names are removed), compressed, sparse and heavily fragmented files, and very large folders.
- Files that Windows tracks in its own hidden indexes (hard links, link-tracking object IDs, reparse points) are refused with a clear message rather than leaving stale data behind. Delete those on a PC.
- For safety, deleting is only available on NTFS drives, not on the PS5's own storage.
- Fixed: the file list didn't always refresh after a very quick copy or delete.

### How deleting stays safe
A deleted file's folder entries are removed first and its space is freed afterwards, so an interruption (e.g. unplugging) can at worst leave an orphaned file or unused space for `chkdsk` to tidy. It never leaves an entry pointing at freed space. Every change to a folder index is validated in memory before anything is written; if a check fails, the delete is refused with nothing changed.

### Testing
- **Delete stress tests:** 4,000 files deleted one by one at 512 B, 4 KB and 64 KB clusters; 8.3-named, compressed, sparse and fragmented files; ten rounds of mixed adds and deletes alternating with ntfs-3g. Every step is checked for index-tree shape, leaked clusters and `ntfsresize --check`, and ntfs-3g reads back every surviving file.
- All earlier reader, writer, fuzzing and server tests still pass.

### Please note
- While it runs, anyone on your local network can browse and **delete** files on writable NTFS drives, as with FTP payloads. Close the payload when you're done, or click the lock to make a drive read-only.
- **Back up anything irreplaceable.** The writer and delete code have not yet been tested with Windows `chkdsk` on drives they've changed, or on a real console.
- Use **Eject** before unplugging a drive you've written to.
